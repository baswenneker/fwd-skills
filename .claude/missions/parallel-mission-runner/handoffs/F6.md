# F6 — integrate-feature.sh

Implemented integrate-feature.sh — the cherry-pick + wave-gate + conflict-policy script for the parallel mission runner. The script resolves its own repo root via rtk git rev-parse (cwd-independent), derives the slot branch as mission/<slug>--f<lowercased-fid>, computes the commit range as merge-base..slot-branch, and handles five paths: happy (cherry-pick in plan order via --empty=drop, optional wave-gates, then the UNCHANGED record-feature.sh records the integrated SHA — exit 0), cherry-pick textual conflict (abort + reset, pin serial_only + discards+1, decision logged, state committed, NO attempt consumed — exit 3), wave-gate failure (this feature's commits reset out back to pre-integration, pin + attempt consumed — exit 4), empty range (no state change — exit 5), and second discard (recorded blocked via record-feature.sh, breaker incremented — exit 6). The mission worktree ends clean and on the mission branch in every path. Slot worktree/branch cleanup is deliberately left to reconcile-waves.sh (F8). SKILL.md's exit-code table and call signature were synced to the concrete contract. All 7 scratch-repo scenario tests pass; G1 and risky-scan clean.

## Issues discovered

- `rtk git status --porcelain` prints "ok" for a clean tree — dirty-tree checks must filter with `grep -vx 'ok'` (mirrors record-feature.sh).
- All git operations referencing mission-repo branches need `-C "$MISSION_WT"` — without it they silently operate on the ambient repo.
- `git worktree add` requires the target dir to not exist.
- bash `(( var++ ))` exits non-zero when the old value is 0, crashing set -e scripts — use `VAR=$((VAR+1))`.

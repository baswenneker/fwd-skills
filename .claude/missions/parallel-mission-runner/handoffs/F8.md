# F8 — reconcile-waves.sh + crash/blocked harness scenarios

Created reconcile-waves.sh (chmod +x): enumerates and removes leftover slot worktrees (`<WT_DIR>/mission/<slug>--slot-*`) via `rtk git worktree remove --force` with rm -rf + prune fallback, removes leftover slot branches via `rtk git for-each-ref 'refs/heads/mission/<slug>--f*'` (glob form — safely excludes the mission branch itself), prints a deterministic slots-removed/slots-clean summary, then DELEGATES to the serial reconcile.sh via exec (invocation, not reimplementation; serial output/exit surface to the caller). Mission worktree and branch untouched — integrated work stays.

Extended smoke-waves.sh: Scenario 8 (crash recovery — wave of 2, FA fully integrated, FB's slot left dangling; reconcile-waves removes FB's slot dir + branch, FA's work and recorded state intact, serial reconcile invoked, FB still pending/re-runnable) and Scenario 9 (second discard → blocked — first conflicting attempt: exit 3, serial_only, discards=1, pending; second: exit 6, blocked, attempts++, breaker++, tree clean). Harness now 73/73 across 5 runs from 3 cwds, ~7.8 s per run.

## Issues discovered

- `for-each-ref` needs the trailing glob (`--f*`) — a bare prefix matches only an exact ref name; the initial implementation had this bug and Scenario 8 caught it.
- record-feature.sh's blocked path doesn't write `discards` (serial shared code, untouchable) — the persisted value stays at the pin's discards=1 when blocked triggers; Scenario 9 asserts accordingly.
- `mapfile` + empty for-each-ref output needs the `${ARR[@]:-}` guard under set -u.

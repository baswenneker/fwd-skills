# F7 — smoke-waves.sh hermetic harness (gate G3)

Created skills/engineering/fwd:mission-run-parallel/tests/smoke-waves.sh — a hermetic bash+jq test harness that fulfils gate G3. The harness builds isolated fixture git repos in mktemp -d directories (cleaned on EXIT trap), never touching the real repo or mission state, and locates the scripts under test relative to its own location. Stub coder = bash helpers committing on slot branches (clean / conflicting / gate-breaking variants). Seven scenarios, 43 assertions: cap enforcement (cap 2, 3 ready → exactly 2 in plan order), integration order (commit_sha advances; FA ancestor of FB), conflict→pin (exit 3, tree clean, serial_only+discards+decision committed, attempts unchanged), wave-gate culprit isolation (exit 4, sentinel reset out, FA intact, FB attempts incremented), v1 refusal (exit 2, stderr mentions /fwd:mission-run), serial_only solo wave, closes_milestone flag. Three consecutive clean runs from three different cwds; the exact G3 gate command line passes from the mission worktree root.

## Left undone (for F8, by design)

- crash→reconcile scenario — fixture builder + assert helpers are function-based for additive extension.
- second-discard→blocked path — cheap F8 extension on the conflict fixture.

## Issues discovered

- setup-slot.sh and pick-wave.sh use bare `rtk git` (no -C) and rely on cwd being inside a git repo — callers outside a git tree must cd first (the harness wraps calls in subshells). Latent gotcha worth knowing for F8/F9.
- record-feature.sh records commit_sha = HEAD before its own checkpoint commit — commit_sha is one commit behind final mission HEAD; assertions check ancestry, not equality.
- macOS /private symlink path duality (mktemp vs git --git-common-dir) is harmless when comparing like-with-like.

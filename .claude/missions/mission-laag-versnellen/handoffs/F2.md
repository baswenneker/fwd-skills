# Handoff F2 — record-feature.sh hardening

## In één oogopslag
`record-feature.sh` weigert niet langer op een untracked handoff-narrative en valideert nu zélf de handoff-JSON. De clean-worktree-check heeft een extra uitzondering gekregen voor untracked bestanden onder `.claude/missions/<slug>/handoffs/` — tracked wijzigingen elders blijven wél een faalreden, zodat echte vuiligheid niet verborgen raakt. In de `done`-tak controleert het script nu, alleen wanneer er echt een handoff-JSON op stdin staat, de vijf verplichte velden en (bij een feature met `rule_paths`) een niet-lege `rules_applied`.

## Bewijs (fixture tegen het échte script, via FWD_MISSION_WORKTREE_DIR)
- happy path met untracked narcotic narrative → exit 0.
- sad path: handoff mist `procedures_followed` → exit 1, melding benoemt het veld.
- sad path: `rule_paths` gevuld maar `rules_applied` leeg → exit 1.
- backward-compat: `blocked` zonder handoff → exit 0.
- negative control: tracked bestand gewijzigd → exit 1 (echte vuiligheid blijft falen).
- `bash -n` op het script → exit 0.

## Keuzes
- Validatie draait alléén in de `done`-tak en alléén wanneer de handoff niet `null` is, zodat de bestaande `blocked`-aanroep en een lege stdin ongewijzigd blijven.
- De checkpoint-commit nam de handoffs-map al mee (`git add` op een directory stageert nieuwe bestanden) — geen wijziging nodig, wel geverifieerd.

# Handoff F5 — Schema v6: depends_on + geblokkeerde features passeren + plan-lint

## In één oogopslag
`pick-next-unit.sh` en `validate-artifacts.sh` ondersteunen nu een optioneel `features[].depends_on`-veld (schema v6, additief) zonder bestaande plannen te breken. Een geblokkeerde feature legt niet langer de hele rij stil: alleen features die er (transitief) van afhangen wachten. De lint keurt `depends_on` af bij een onbekende feature-id, een vooruit-verwijzing of een cykel. Uitvoering blijft strikt serieel — geen parallelle machinerie toegevoegd.

## Wat is er gewijzigd
- **`pick-next-unit.sh`**: slaat `blocked`-features over en features die (transitief) van een niet-done feature afhangen. Nieuwe exit-conventie: lege stdout + exit 0 bij "alles done"; lege stdout + exit 3 + stderr-melding bij "vastgelopen achter geblokkeerd werk". Een plan zónder `depends_on` gedraagt zich exact als voorheen.
- **`validate-artifacts.sh`**: lint `depends_on` (onbekende id, vooruit-verwijzing, cykel) met cycle-guard; benoemt de overtredende feature; plannen zónder het veld passeren ongewijzigd.
- **`REFERENCE.md`**: `depends_on` gedocumenteerd als additief schema-v6-veld.
- **`SKILL.md` stap 2.1**: één zin over het passeren van geblokkeerde features en het exit-0/exit-3-onderscheid.

## Bewijs (fixtures tegen de échte scripts, in een tmp-repo)
- A blocked, B onafhankelijk → output B (exit 0).
- A blocked, B depends_on A → geen werk, blokkade-melding (exit 3).
- v1 state zonder depends_on → eerste niet-done feature (exit 0), identiek aan voorheen.
- depends_on naar onbestaande id / vooruit-verwijzing / cykel → lint exit 1, feature benoemd.
- geldig plan met correcte depends_on → lint exit 0.
- `bash -n` op beide scripts → exit 0.

## Aandachtspunt voor de reviewer
De nieuwe exit-3-conventie is een gedragsverandering in `pick-next-unit.sh`: callers die "lege stdout = alles done" aannemen moeten exit 3 (blokkade) onderscheiden van exit 0 (klaar). SKILL.md stap 2.1 documenteert dit; controleer of de orchestrator-flow (stap 2.1 → 3 finalize) het onderscheid respecteert.

# Validation Contract: mission-laag-versnellen

Alle assertions zijn `scrutiny-review` — deze repo heeft geen bootbare app; die keuze is expliciet vastgelegd in `mission.md` §Aannames en afwijkingen.

## Layer A — Gates (machine-checked, exit 0)
| ID | Name | Command |
|----|------|---------|
| G1 | shell-syntax | `find skills agents -name '*.sh' -print0 \| xargs -0 -n1 bash -n` |

## Layer B — Assertions (judged)

### M1 — Agent-definities zelfvoorzienend

- **VC-1** (scrutiny-review): *Given* de 5 agent-definities (`agents/fwd-mission-coder.md`, `fwd-mission-reviewer.md`, `fwd-mission-user-tester.md`, `fwd-steps-reviewer.md`, `fwd-steps-doubt.md`), *when* de reviewer ze doorzoekt op verwijzingen naar `CONTEXT.md` of andere bestanden die alleen in fwd-skills bestaan, *then* komen zulke verwijzingen niet meer voor en staan de benodigde normen (Codecommentaar-kern, advisory/concern-definitie, schrijfstijl-kern) letterlijk inline in elk agent-bestand dat ze nodig heeft. · *Agents zoeken nooit meer naar een bestand dat niet in de doelrepo bestaat.* *(features: F1)*
- **VC-2** (scrutiny-review): *Given* de 5 agent-definities, *when* de reviewer de instructies leest, *then* bevat elk bestand het gedragsverbod: nooit rtk-output in een tweede rtk-aanroep pipen; `rtk git` voor git-commando's, gewone tools (`cat`/`grep`/`head`) voor inspectie; nooit buiten de repo-root zoeken (`find /` is verboden) — ontbreekt een genoemd bestand, dan meldt de agent dat in zijn verdict in plaats van te gaan zoeken. · *Geen 120-seconden-timeouts en geen schijf-brede zoektochten meer.* *(features: F1)*
- **VC-3** (scrutiny-review): *Given* de inline normblokken in de agent-definities en de bronblokken in `CONTEXT.md` van fwd-skills, *when* de reviewer ze naast elkaar legt, *then* dekken de inline blokken dezelfde normen zonder betekenisverlies (parafrase mag; weglaten van een norm niet). · *Sneller maakt niet slordiger: de norm blijft dezelfde.* *(features: F1)*
- **VC-4** (scrutiny-review): *Given* de gecommitte code van deze milestone, *when* de reviewer de diff leest, *then* bevat geen enkele comment, docstring of commit message een mission-interne code (feature-ID, milestone-ID, VC-ID of historie-verwijzing zoals "pre-F4") — elke comment is zelfstandig leesbaar. · *Comments leggen het wat/waarom uit, zonder mission-jargon.* *(features: F1)*
- **VC-5** (scrutiny-review): *Given* de bewijsvoering die deze milestone toevoegt (`handoff.commands` en eventuele fixtures), *when* de reviewer die leest, *then* draait elk bewijscommando de échte bestanden uit deze repo (geen nagebootste kopie in een fixture die het echte script omzeilt) en is geen bewijs tautologisch (een check die ook slaagt als de wijziging ontbreekt). · *Het groene bewijs bewijst echt gedrag.* *(features: F1)*
- **VC-6** (scrutiny-review): *Given* de gecommitte code van deze milestone, *when* de reviewer de diff leest, *then* introduceert de diff geen dependency, abstractie of top-level map buiten deze lijsten — toegestane nieuwe dependencies: geen; toegestane nieuwe abstracties: plugin-agent `agents/fwd-mission-scribe.md`, `state.json`-velden `features[].depends_on`, `features[].reading_list`, `features[].size` (schema v6, additief). · *De code blijft binnen het afgesproken design budget.* *(features: F1)*

### M2 — Run-machinerie goedkoper

- **VC-7** (scrutiny-review): *Given* een fixture-missie met een untracked handoff-narrative onder `.claude/missions/<slug>/handoffs/`, *when* `record-feature.sh` draait voor een geldige feature-afronding, *then* eindigt het script met exit 0 en een correct bijgewerkt `state.json` — het untracked narrative-bestand is geen faalreden meer. · *De frictie die in de gemeten run een extra denk-loop kostte, is weg.* *(features: F2)*
- **VC-8** (scrutiny-review): *Given* een fixture-missie, *when* `record-feature.sh` een handoff-JSON krijgt zonder de verplichte velden (`implemented`, `left_undone`, `commands`, `issues_discovered`, `procedures_followed`) óf zonder niet-lege `rules_applied` terwijl de feature `rule_paths` heeft, *then* weigert het script met non-zero exit en een foutmelding die het ontbrekende veld benoemt. · *De handoff-validatie zit in het script, niet meer in dure denk-stappen van de orchestrator.* *(features: F2)*
- **VC-9** (scrutiny-review): *Given* de diff, *when* de reviewer `agents/fwd-mission-scribe.md` en `skills/engineering/fwd:mission-run/SKILL.md` stap 2.5 leest, *then* bestaat de scribe-agent met `model: haiku` en een tools-allowlist zonder `Write`/`Edit`, en draagt SKILL.md het compileren van de milestone-walkthrough op aan de scribe waarna de orchestrator het resultaat wegschrijft en commit. · *Samenvatten gebeurt op het goedkope model; schrijven blijft bij de orchestrator.* *(features: F3)*
- **VC-10** (scrutiny-review): *Given* `agents/fwd-mission-scribe.md`, *when* de reviewer de instructies leest, *then* bevat de scribe de volledige verificatiepas (elk genoemd pad tegen `rtk git -C <WT> diff --name-only <range>` of bestaan op HEAD; elk genoemd symbool gegrept in zijn bestand; mismatch → corrigeren vóór oplevering) en de verplichte slotregel "Verificatie: <n> paden en <n> symbolen gecontroleerd tegen de diff." · *Haiku mag samenvatten, niet bluffen.* *(features: F3)*
- **VC-11** (scrutiny-review): *Given* `skills/engineering/fwd:mission-run/SKILL.md`, *when* de reviewer de reviewer-spawn-instructie in stap 2.5 leest, *then* schrijft die voor dat de prompt de gate-uitslag (`gate_results`) en de commit-SHA van de milestone-range meekrijgt, met de instructie: draai geen volledige testsuite opnieuw zolang de SHA gelijk is aan die van de gate-run — alleen gerichte tests bij concrete twijfel. · *Maximaal één volledige suite-run per milestone op ongewijzigde code.* *(features: F3)*
- **VC-12** (scrutiny-review, afspraak): *Given* de volledige diff van deze milestone, *when* de reviewer alle gewijzigde instructieteksten leest, *then* is geen enkel oordeel (handoff accepteren/afwijzen, remediatie-beslissing, keuze van de volgende unit, verdicts) gedelegeerd aan de scribe of aan een ander niet-hoofdmodel — de scribe compileert uitsluitend de walkthrough. · *Afspraak met de gebruiker: het besliswerk blijft bij het hoofdmodel.* *(features: F3)*
- **VC-13** (scrutiny-review): *Given* de gecommitte code van deze milestone, *when* de reviewer de diff leest, *then* bevat geen enkele comment, docstring of commit message een mission-interne code of historie-verwijzing — elke comment is zelfstandig leesbaar. · *Comments leggen het wat/waarom uit, zonder mission-jargon.* *(features: F2, F3)*
- **VC-14** (scrutiny-review): *Given* de bewijsvoering die deze milestone toevoegt (fixture-runs in `handoff.commands`), *when* de reviewer die leest, *then* roepen de fixtures het échte `record-feature.sh` uit deze repo aan (geen gekopieerde logica) en is geen bewijs tautologisch — de sad-path-fixture faalt aantoonbaar wanneer de validatie zou ontbreken. · *De groene fixtures bewijzen echt gedrag.* *(features: F2, F3)*
- **VC-15** (scrutiny-review): *Given* de gecommitte code van deze milestone, *when* de reviewer de diff leest, *then* introduceert de diff geen dependency, abstractie of top-level map buiten deze lijsten — toegestane nieuwe dependencies: geen; toegestane nieuwe abstracties: plugin-agent `agents/fwd-mission-scribe.md`, `state.json`-velden `features[].depends_on`, `features[].reading_list`, `features[].size` (schema v6, additief). · *De code blijft binnen het afgesproken design budget.* *(features: F2, F3)*

### M3 — Plan-laag: minder spawns, slimmere spawns

- **VC-16** (scrutiny-review): *Given* `skills/engineering/fwd:mission-plan/SKILL.md` en `REFERENCE.md`, *when* de reviewer stap 3 en de grill (stap 4.5) leest, *then* staat daar de sizing-regel — een feature is ~30–45 minuten bouwwerk; kleinere verwante units worden samengevoegd — onderbouwd met het spawn-belasting-argument (elke verse coder betaalt oriëntatie- en afrondingstijd), en toetst de grill expliciet op te fijn gesneden plannen. · *Nooit meer 14 spawns rond 46 minuten bouwwerk.* *(features: F4)*
- **VC-17** (scrutiny-review): *Given* een fixture-missie waarin feature A `blocked` is en feature B niet van A afhangt (`depends_on` ontbreekt of noemt A niet), *when* `pick-next-unit.sh` draait, *then* levert het feature B op in plaats van te blijven hangen op A; hangt B wél (transitief) van A af, dan levert het geen werk en meldt het de blokkade. · *Eén blokkade legt alleen echte afhankelijken stil, niet de hele rij.* *(features: F5)*
- **VC-18** (scrutiny-review): *Given* een fixture met een v1-`state.json` zonder `depends_on`/`reading_list`/`size`, *when* dezelfde scripts (`pick-next-unit.sh`, `record-feature.sh`, `validate-artifacts.sh`) erop draaien, *then* is het gedrag identiek aan het huidige gedrag (zelfde output, zelfde exit codes) — alle nieuwe velden zijn additief. · *Bestaande missies breken niet.* *(features: F5)*
- **VC-19** (scrutiny-review): *Given* een fixture-plan met een `depends_on` naar een niet-bestaande feature, naar een látere feature in de array, of met een cykel, *when* `validate-artifacts.sh` draait, *then* faalt het met non-zero exit en benoemt het de overtredende feature. · *Kapotte afhankelijkheden komen de run nooit in.* *(features: F5)*
- **VC-20** (scrutiny-review): *Given* `skills/engineering/fwd:mission-run/SKILL.md` stap 2.3 en `fwd:mission-plan` stap 6, *when* de reviewer ze leest, *then* genereert het plan per feature een `reading_list` (uit de file-by-file-tabel) en schrijft de coder-spawn-prompt voor: de reading-list meegeven, de inhoud van de gematchte rule-bestanden inline opnemen wanneer die samen < ~200 regels zijn (anders de paden-lijst als fallback), en de instructie "lees alléén dit; scan de repo niet opnieuw". · *De ~9 minuten oriëntatie per coder gaat fors omlaag.* *(features: F6)*
- **VC-21** (scrutiny-review): *Given* dezelfde documenten, *when* de reviewer stap 2.3 leest, *then* is daar een model/effort-richtlijn naar featuregrootte gedocumenteerd op basis van het additieve veld `features[].size` (S/M/L; bij S een lager effort of lichter model, bij ontbreken van het veld het huidige gedrag). · *Geen top-model op vol vermogen voor een metrics-bestandje.* *(features: F6)*
- **VC-22** (scrutiny-review, afspraak): *Given* de volledige diff van deze missie, *when* de reviewer zoekt naar parallelle-uitvoering-machinerie, *then* bevat de diff géén sub-worktree-scripts, geen merge-scripts en geen instructie om coders parallel te spawnen — afhankelijkheden worden alleen vastgelegd (`depends_on`) en gebruikt om geblokkeerde features te passeren; uitvoering blijft serieel. · *Afspraak met de gebruiker: waves geschrapt, alleen de informatie wordt bewaard.* *(features: F5)*
- **VC-23** (scrutiny-review): *Given* de gecommitte code van deze milestone, *when* de reviewer de diff leest, *then* bevat geen enkele comment, docstring of commit message een mission-interne code of historie-verwijzing — elke comment is zelfstandig leesbaar. · *Comments leggen het wat/waarom uit, zonder mission-jargon.* *(features: F4, F5, F6)*
- **VC-24** (scrutiny-review): *Given* de bewijsvoering die deze milestone toevoegt (fixture-runs in `handoff.commands`), *when* de reviewer die leest, *then* draaien de fixtures de échte scripts uit deze repo en is geen bewijs tautologisch — de lint-fixtures (VC-19) falen aantoonbaar op een kapot plan en slagen op een geldig plan. · *De groene fixtures bewijzen echt gedrag.* *(features: F4, F5, F6)*
- **VC-25** (scrutiny-review): *Given* de gecommitte code van deze milestone, *when* de reviewer de diff leest, *then* introduceert de diff geen dependency, abstractie of top-level map buiten deze lijsten — toegestane nieuwe dependencies: geen; toegestane nieuwe abstracties: plugin-agent `agents/fwd-mission-scribe.md`, `state.json`-velden `features[].depends_on`, `features[].reading_list`, `features[].size` (schema v6, additief). · *De code blijft binnen het afgesproken design budget.* *(features: F4, F5, F6)*

## Robuustheid

Per feature de sad-path-/schaal-dekking, of de expliciete waiver. Realistische-schaal-VC's zijn n.v.t. — geen feature raakt externe of live data.

- **F1**: VC-3 (norm-drift is het faalpad: inline blok wijkt af van de bron)
- **F2**: VC-8 (ongeldige handoff-JSON wordt geweigerd)
- **F3**: VC-10 (scribe zonder verificatiepas zou bluffen — het faalpad is afgedekt in de agent-instructie zelf)
- **F4**: waiver — documentatieregel zonder foute input; expliciet bevestigd door de gebruiker (AskUserQuestion, 8 juli 2026)
- **F5**: VC-18 (oud plan blijft werken) + VC-19 (kapotte depends_on faalt de lint)
- **F6**: VC-20 (fallback naar paden-lijst wanneer rules > ~200 regels — het te-groot-pad is gedekt)

## App boot (user-testing)

Geen — bewust geaccepteerd: deze repo is een skills-plugin zonder bootbare app. Alle VC's zijn `scrutiny-review`; er zijn geen user-testing-VC's en geen `boot_command`.
